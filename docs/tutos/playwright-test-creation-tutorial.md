# Tutorial: Creating a Playwright Test File Manually

This guide explains how to create a Playwright end-to-end (E2E) test file in TypeScript, using the Playwright Inspector to help generate test steps. We'll use a signup page as our example.

## 1. File Structure and Naming Convention

Playwright tests are typically located in a `tests` directory at the root of your project. Test files follow a specific naming convention so the test runner can find them:

-   **`<name>.spec.ts`**: For general tests.
-   **`<name>.e2e.spec.ts`**: For end-to-end tests.
-   **`<name>.integration.spec.ts`**: For integration tests.

For our example, we will create a file named `signup.e2e.spec.ts` inside the `tests` directory.

## 2. Basic Test Structure

Every test file will import the `test` and `expect` functions from `@playwright/test`. The basic structure is a `test` block, which contains the test logic.

```typescript
// tests/signup.e2e.spec.ts
import { test, expect } from '@playwright/test';

test('should allow a user to sign up successfully', async ({ page }) => {
  // Test steps will go here
});
```

## 3. Using Playwright Inspector (Codegen) to Generate Steps

Playwright's Codegen tool is a powerful feature that watches your interactions with a webpage and generates the corresponding TypeScript code. This is the recommended "manual" way to create tests, as it's fast and accurate.

### How to Run Playwright Codegen:

1.  Open your terminal.
2.  Run the following command, replacing `http://localhost:3000/signup` with the actual URL of your signup page:

    ```bash
    npx playwright codegen http://localhost:3000/signup
    ```

3.  This command opens two windows:
    *   A browser window where you can interact with your application.
    *   The Playwright Inspector window, which will show the generated code in real-time.

### Generating the Test Steps:

1.  In the browser window, perform the actions a user would take to sign up:
    *   Click on the email input field.
    *   Type an email address.
    *   Click on the password input field.
    *   Type a password.
    *   Click the "Sign Up" button.

2.  As you perform these actions, you will see the corresponding code appear in the Playwright Inspector window.

3.  After signing up, a user might be redirected to a dashboard page and see a "Welcome" message. To verify this, use the Inspector's "Assert visibility" feature to add an assertion that confirms the welcome message is visible.

The generated code will look something like this:

```typescript
// Generated by Playwright Codegen

await page.goto('http://localhost:3000/signup');
await page.getByPlaceholder('Enter your email').click();
await page.getByPlaceholder('Enter your email').fill('test@example.com');
await page.getByPlaceholder('Enter your password').click();
await page.getByPlaceholder('Enter your password').fill('password123');
await page.getByRole('button', { name: 'Sign Up' }).click();
await expect(page.getByText('Welcome to your dashboard!')).toBeVisible();
```

## 4. Assembling the Final Test File

Now, copy the generated code from the Playwright Inspector into your test file.

Here is the complete `signup.e2e.spec.ts` file:

```typescript
// tests/signup.e2e.spec.ts
import { test, expect } from '@playwright/test';

test.describe('Signup Flow', () => {
  test('should allow a user to sign up successfully', async ({ page }) => {
    // 1. Navigate to the signup page
    await page.goto('http://localhost:3000/signup');

    // 2. Fill out the form
    await page.getByPlaceholder('Enter your email').fill('test@example.com');
    await page.getByPlaceholder('Enter your password').fill('password123');

    // 3. Click the sign-up button
    await page.getByRole('button', { name: 'Sign Up' }).click();

    // 4. Verify successful registration
    // This is a crucial step. Check for something that only appears after a successful signup.
    await expect(page).toHaveURL(/.*dashboard/); // Check if the URL changed to the dashboard
    await expect(page.getByText('Welcome to your dashboard!')).toBeVisible(); // Check for a welcome message
  });
});
```

## 5. Running Your Test

You can run your new test from the terminal:

```bash
# Run a specific test file
npx playwright test tests/signup.e2e.spec.ts

# Run all tests
npx playwright test
```

## Best Practices

*   **Use Locators Instead of CSS/XPath Selectors**: Use `getByRole`, `getByText`, `getByLabel`, etc. They are more resilient to code changes than CSS classes or XPath.
*   **Use `test.describe`**: Group related tests together using `test.describe` for better organization.
*   **Add Assertions**: A test without assertions is not a test. Always use `expect` to verify that your application behaves as intended.
*   **Don't Rely Solely on Codegen**: Codegen is a great starting point, but you should always review and refine the generated code to make it more robust and readable.
